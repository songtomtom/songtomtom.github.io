코딩 에이전트를 쓰다 보면 프로젝트 규칙 파일이 자랍니다. 지키라고 적은 것, 만드는 절차, 그렇게 정한 이유, 예외가 한 파일에 쌓이고, 길어질수록 에이전트는 그중 일부만 따릅니다. 이 시리즈는 그 파일을 어떻게 나누고, 글로 적은 금지를 어떻게 실행 경로로 옮기고, 역할이 다른 일을 어떻게 다른 에이전트에 맡기는지를 다룹니다.

다른 글과 다른 점은 **층을 하나 올릴 때마다 같은 작업을 다시 돌려 전후를 잰다**는 것입니다. 저장소에는 고정 작업과 자동 채점기가 들어 있고, 글의 수치는 전부 거기서 나온 것입니다. 효과가 없으면 없다고 씁니다.

예제 코드베이스는 [Nx + pnpm 모노레포](/series/nx-vite-pnpm-monorepo)의 할 일 보드에 디자인 토큰과 i18n을 더한 것입니다. 지킬 규칙이 저절로 생기는 크기입니다.

여섯 편입니다.

1. 규칙·절차·결정을 세 층으로 나누기 — 비용은 안 줄고 구조가 바뀐다
2. 절차형 Skill — 승인 게이트와 안전 규칙이 있는 QA 세션
3. Hook은 어떻게 우회되는가 — 쓰기 도구가 아니라 결과를 검사하기
4. 역할이 다른 일은 다른 에이전트가 — 정의만으로는 호출되지 않는다
5. 하네스가 맞는지 증명하기 — 평가 세트와 채점기가 틀린 세 번
6. 616줄에서 배운 것 — 다음에 세운다면 어떤 순서로
